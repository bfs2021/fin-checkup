# 기업분석 허브 — 설계

2026-11-21 · 상태: 진행 중 (2026-11-21 사용자가 자율 진행 지시)

## 왜

지금 fin-checkup 을 쓰려면 `uv`·DART 인증키·CLI 를 거쳐야 한다. 주식을 하는 일반인은 여기서 거의 다 떠난다.
목표는 **누구든지 회사 이름 하나로 그 회사의 재무상태를 정확히 이해하고, 그 이해가 쌓여서 다시 찾아오는 곳**
— "기업분석의 성지" — 이다. 개발자는 같은 데이터를 정적 JSON 으로 재사용한다.

**완료 기준:** main 에 의미 있는 PR 50개 이상 병합 (50 은 하한 — 미룬 항목은 다른 실제 작업으로 채운다, 쪼개기 금지) · GitHub Pages 사이트가 전 상장사(최신 사업연도) 페이지를
서빙 · 모든 페이지가 면책·계산식 가드 테스트를 통과 · CI 녹색. 진척은 `docs/superpowers/plans/` 의 계획서에 적는다.

## 목표 / 비목표 / 반목표

**목표**
- 설치 0, 가입 0: 브라우저에서 회사 이름을 치면 신호등 페이지.
- 숫자마다 "이게 뭐고, 왜 이 색인가"를 쉬운 말로 — 계산식·경계값·동종업계 분위수와 함께.
- 쓸모 때문에 돌아오게: 관심종목의 변화, 사업보고서 시즌 안내, 피드, 공유 카드.
- 검색 유입: 회사별 정적 HTML, sitemap, OG 메타.

**비목표 (이번엔 안 함)**
- 실시간 서버·로그인·계정. 기존 CLI/Streamlit/FastAPI 는 그대로 두고 건드리지 않는다.
- 커스텀 도메인 구매 (사용자 결정. 기본 주소는 `younghwan91.github.io/fin-checkup`).
- 외부 커뮤니티 게시 — 마케팅 문안은 초안까지, 게시는 사용자가 한다.

**반목표 (기술적으로 돌아가도 이러면 실패다)**
- **추천처럼 읽히는 것**: "이번 주 주목할 종목", "재무 우량주 TOP 10", 매수/매도를 재촉하는 문장, 계산식을 감춘
  종합 점수. 시장 전체 목록은 이름순·업종순만 쓰고 지표 순위표는 만들지 않는다 (`docs/REGULATORY.md`).
- **중독 설계**: 무한 피드, 스트릭, 빨간 숫자 배지, "놓치면 손해" 류의 긴급 알림, 가변 보상. 금융에서 이건
  충동 매매를 부추긴다. 인스타그램에서 가져오는 건 *진입 마찰 제거·탐색 동선·공유·저장*이지 *강박*이 아니다.
- **데이터 위조**: 없는 계정을 0 으로, 맞지 않는 업종 지표를 판정으로 내보내는 것 (⚫·⊘ 규칙 그대로).
- **개인정보 유출**: 캐시 DB 의 `accounts`·`api_keys`·`subscriptions`·`watchlist`·`notified`·`usage_daily`·
  `dart_call_log` 는 어떤 산출물에도 들어가지 않는다. 사이트는 추적 스크립트·쿠키를 쓰지 않는다.

## 사람이 돌아오는 고리 (윤리적 Hook 모델)

| 단계 | 인스타그램 | 여기서 |
|---|---|---|
| 계기 | 알림·심심함 | 관심종목 등급 변화, 사업보고서 시즌(3·5·8·11월), 회사별 Atom 피드, 지인이 공유한 카드 |
| 행동 | 앱 열기 한 번 | 검색창 하나 — 이름·종목코드·초성(`ㅅㅅㅈㅈ`) |
| 보상 | 가변 피드 | **"아, 그래서 빨간색이구나"** 이해의 보상. 같은 업종 회사·같은 지표 해설로 이어지는 탐색 동선 |
| 투자 | 팔로우·저장 | 브라우저에 저장된 관심종목 → 다음 방문에 "지난번 이후 바뀐 것" 이 보인다 |

공유 단위는 **카드뉴스**다 — 한국 인스타그램 금융 콘텐츠의 표준 형식. 회사 한 곳의 신호등 요약을 1080×1350
이미지 몇 장으로 만들고, 모든 장에 면책 문구와 출처(DART)를 박는다.

## 제약

- `docs/REGULATORY.md` 의 선, CLAUDE.md 의 ⚫·⊘ 규칙, 경계값은 `metrics/engine.py` 를 그대로 쓴다(재정의 금지).
- 사이트 빌드는 **캐시만 읽는다** — DART 호출 0. 데이터 수집(`scripts/collect_universe.py`)과 분리한다.
- DART 인증키는 산출물·로그·HTML 어디에도 없다. 공시 피드처럼 매일 DART 를 불러야 하는 기능은 Actions secret 이
  필요하고, 그 secret 등록은 사용자가 한다.
- 날짜는 KST(`clock.kst_today`). 페이지마다 "데이터 기준: 2025 사업연도 · 빌드 2026-11-21" 을 표시한다.
- 모든 PR 은 브랜치 → PR → CI 녹색 → `gh pr merge --merge --delete-branch`. 커밋은 한국어 Conventional Commits.
- 포맷: 새 파일만 ruff format, 기존 파일 전체 재포맷 금지.

## 방식 (Approaches)

| | 방식 | 판단 |
|---|---|---|
| **A (채택)** | 정적 사이트 생성기: 캐시 → 회사별 HTML + JSON → GitHub Pages | 설치·서버·비용 0, 검색 노출, 키가 밖으로 나가지 않음, DuckDB 단일 writer 문제 없음. 대신 하루 단위 갱신 |
| B | Streamlit/FastAPI 호스팅 | 실시간이지만 서버 비용·운영키 상주·단일 writer 충돌, Streamlit 은 SEO 가 약하다 |
| C | 설치 간소화 (원클릭 설치기) | 여전히 개발자 대상. "누구든지" 에 못 미친다 |

사용자는 "어떻게"를 맡겼고, A 는 Claude 의 판단이다.

## 설계

### 구조

```
src/fin_checkup/site/
  build.py       # 캐시 → Checkup 계산 → 렌더 → out/ (service.py 재사용, UI 를 모르는 원칙 유지)
  render.py      # Jinja2 템플릿 렌더
  explain.py     # 지표·위험신호·공시유형 해설 데이터 + "왜 이 색" 문장 (템플릿 문장, 판단 아님)
  charts.py      # 추이·분포를 JS 없이 인라인 SVG 로
  snapshot.py    # 공개 스냅샷 export — 테이블 허용목록 방식
  templates/  static/  (CSS·검색·관심종목 JS, 바닐라)
cli: `site build [--year] [--out site-out] [--limit N]`, `site snapshot`
```

### 페이지

- `/` 검색 + 사업보고서 시즌 안내 + 처음 오셨나요(가이드 링크).
- `/c/<종목코드>/` 회사: 17개 지표 신호등, 지표마다 "왜 이 색" 한 문장(값·경계값·업종 분위수), 위험 신호,
  5개년 추이 SVG, 동종업계 분포 위 내 위치, 같은 업종 회사(이름순), 원문 DART 링크, 관심종목 버튼, 공유 카드.
- `/m/<지표>/` 지표 해설 17개: 쉬운 정의 · 왜 보나 · 한계 · 업종별 주의 · 실제 숫자로 계산해 보기.
  예시 회사는 색과 무관한 고정 규칙(업종별 매출 최대 회사)으로 고르고, 계산 과정을 보여 줄 뿐 "좋다/나쁘다"
  수식어를 붙이지 않는다. *(Claude 판단 — 색으로 골라 띄우면 추천처럼 읽힌다)*
- `/s/<업종>/` 업종: 지표별 분포(중앙값·사분위), 소속 회사 이름순. 순위표 없음.
- `/learn/` 재무제표 처음 읽기, 업종별 읽는 법, 위험 공시 유형 해설, 용어집.
- `/compare/?c=005930,000660` 2~4개 비교 (정적 JSON 을 브라우저에서 합침).
- `/watch/` 관심종목 (localStorage) + 지난 방문 이후 바뀐 것.
- `/api/c/<종목코드>.json`, `/feeds/c/<종목코드>.xml`, `sitemap.xml`, `robots.txt`, `404.html`,
  임베드용 배지 `/badge/<종목코드>.svg`.
- 미국: SEC 데이터가 캐시에 있는 회사만 `/us/<티커>/` (후순위).

### 데이터·배포

1. 로컬 `~/git/fin-checkup` 에서 2025 사업연도 전 상장사를 먼저 수집하고(하루 한도 20,000 안), 이어지는 날에
   2022·2021 을 채운다. 추이 차트는 캐시에 있는 해만큼 그린다 — 없는 해는 ⚫ 칸으로 남긴다. *(Claude 판단)*
2. `site snapshot` 이 허용목록 테이블(`companies`, `corp_codes` 중 상장사, `statement_lines`, `metric_values`,
   `fetch_misses`)만 parquet 로 뽑아 GitHub Release 자산으로 올린다. 허용목록 밖 테이블이 끼면 테스트가 실패한다.
3. `pages.yml` 워크플로가 스냅샷을 내려받아 `site build` → Pages 배포. 수동 실행 + 스냅샷 릴리스 시 실행.
4. (secret 등록 후) 일별 크론으로 공시 목록 갱신 → 피드·"최근 위험 공시" 섹션.

### 가드 (같은 종류의 실수를 다시 못 하게)

- 생성된 모든 HTML 에 `DISCLAIMER` 가 있고, 판정 지표마다 계산식·경계값이 있는지 검사하는 테스트.
- 금지 문구 린트: "추천·매수·매도·사세요·파세요·유망·TOP" 등이 템플릿·해설 데이터·카드에 없음.
- 스냅샷 허용목록 테스트, 산출물에 인증키 패턴이 없음을 확인하는 테스트.
- 외부 스크립트·추적기 없음 (CSP 메타 + 테스트).
